# Система использования предметов

## Назначение

Система замыкает игровой цикл `добыча → инвентарь → применение → изменение состояния → сохранение` без размещения правил предметов внутри UI.

Godot: **4.7.1 Standard**. Основная платформа: Android.

## Данные

Применяемые предметы описаны в `data/items/item_use_definitions.json`. Каталог объединяется с основным `data/items/items.json` через `game_state_item_use.gd`, поэтому существующие стабильные `item_id` и старые сохранения не меняются.

Контракт `use_action`:

- `inventory_label` — подпись кнопки в инвентаре;
- `action_label` — конкретное русское действие в игровом каталоге;
- `target_mode` — способ выбора цели;
- `combat_cost` — `action`, `bonus_action` или `none`;
- `allowed_in_combat` — разрешение использования во время инициативы;
- `consumption_mode` — `consume_one` или `none`;
- `effect_id` — тип доменного эффекта;
- `effect_parameters` — параметры эффекта.

## Транзакции

Расходуемый предмет проходит существующий контракт:

1. `reserve_inventory_item()`;
2. повторная валидация цели и состояния;
3. оплата боевого действия;
4. `commit_inventory_transaction()`;
5. применение эффекта.

Если действие уже потрачено, цель стала недопустимой или игрок отменил применение до подтверждения, выполняется `rollback_inventory_transaction()`. Незавершённые резервы не сохраняются.

## Реализованные предметы

### Зелье лечения

- `item_id`: `potion_of_healing`;
- восстанавливает `2к4 + 2` HP;
- не применяется при полном HP;
- в бою расходует основное действие;
- списывается ровно одна единица;
- восстановление с 0 HP очищает состояние спасбросков смерти игрока.

### Набор лекаря

- `item_id`: `healers_kit`;
- расходует одно применение;
- стабилизирует цель, реализующую контракт `can_be_stabilized_with_healers_kit()` / `stabilize_with_healers_kit()`;
- не восстанавливает HP;
- в бою расходует основное действие;
- несмертельно оглушённый NPC не считается автоматически умирающим.

Текущий караульный пост не содержит управляемого союзника со спасбросками смерти. Поэтому пользовательский путь набора лекаря станет доступен при добавлении первого умирающего союзника; доменный контракт и автоматический тест уже готовы.

### Записка Смотрителя

- `item_id`: `caretaker_field_note`;
- не расходуется;
- недоступна во время боя;
- устанавливает постоянный сюжетный флаг `caretaker_field_note_read`;
- показывает русское содержание записки.

## UI

`InventoryPanel` только отображает data-driven кнопку и отправляет `item_use_requested(item_id)`. Он не изменяет HP, инвентарь или сюжетные флаги.

Игровой runtime добавляет конкретные действия, например:

- `ВЫПИТЬ: ЗЕЛЬЕ ЛЕЧЕНИЯ`;
- `СТАБИЛИЗИРОВАТЬ: <ИМЯ>`;
- `ПРОЧИТАТЬ: ЗАПИСКА СМОТРИТЕЛЯ`.

## Сохранения

Формат сохранения не повышается. Используются уже существующие поля:

- количество предметов — `inventory`;
- прочитанная записка — `story_flags`;
- здоровье — `player_character`.

Старые сохранения без новых предметов загружаются без миграции.

## Проверки

- подготовка, резерв, commit и rollback;
- точное лечение с детерминированным броском;
- запрет лечения при полном HP;
- стабилизация и защита от повторного расхода;
- нерасходуемый сюжетный предмет;
- русские подписи действий;
- кнопка использования в реальном инвентаре;
- расход основного действия в бою;
- запрет чтения записки в бою;
- совместимость с контейнерами и базовым каталогом предметов.

## Не входит в этап

- использование предметов NPC;
- передача зелий союзникам;
- метание зелий;
- факелы и динамический свет;
- алхимия;
- вес и общий лимит инвентаря;
- ключи, замки и ловушки.
