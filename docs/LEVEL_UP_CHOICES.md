# Универсальные выборы при повышении уровня

## Цель

Система расширяет транзакционное повышение уровня без создания отдельного окна и отдельного сохранения для каждого класса.

Игровой контракт:

```text
LevelUpSystem
→ LevelUpChoiceSystem
→ LevelChoiceSystem
→ data/rules/level_choices.json
→ PlayerCharacter
```

`LevelUpChoiceSystem` наследует уже проверенную транзакцию HP, классовых заклинаний и Magic Initiate. Все решения сохраняются внутри той же незавершённой транзакции под ключом `level_choices`.

## Данные

Каталог `data/rules/level_choices.json` содержит:

- глобальные выборы конкретного уровня;
- классовые выборы конкретного уровня;
- стабильные ID подклассов;
- доступные функциональные черты;
- имена характеристик и ограничение значения 20.

Пример определения:

```json
{
  "choice_id": "fighter_subclass",
  "type": "subclass",
  "required": true,
  "count": 1,
  "options": ["guardian_vanguard", "tactical_blade"]
}
```

UI не содержит список подклассов, черт или правил повышения характеристик. Он строит элементы из каталога.

## Состояние персонажа

`PlayerCharacter` хранит:

- `subclass_id` и `subclass_name`;
- `level_feat_ids` отдельно от `origin_feat_id`;
- `level_ability_bonuses` как источник уровневых увеличений;
- `level_choice_history` с уровнем, типом и выбранными стабильными ID.

Это позволяет отличать:

```text
origin_feat_id
level_feat_ids
known_features
```

`known_features` остаётся агрегированным runtime-списком. Источник решения хранится отдельно.

## Поддерживаемые решения

### Уровень 3, Воин

Обязательный выбор одного пути:

- `guardian_vanguard` — «Страж передовой»;
- `tactical_blade` — «Тактический клинок».

На этом этапе выбор фиксирует идентичность подкласса и точку расширения. Уровневые способности этих путей должны добавляться последующими отдельными механическими PR.

### Уровень 4, все классы

Обязателен один вариант:

1. `ability_plus_two` — +2 к одной характеристике;
2. `ability_plus_one_each` — +1 к двум разным характеристикам;
3. `feat` — одна доступная функциональная черта.

Характеристика не может превысить 20. Вариант +1/+1 требует две разные характеристики.

В первом каталоге доступны:

- `alert`;
- `savage_attacker`.

Они используют существующую механику и работают независимо от того, получены из происхождения или за уровень. Повторный выбор уже имеющейся неповторяемой черты запрещён.

## Транзакция

Неполный обязательный выбор блокирует кнопку подтверждения. Закрытие панели сохраняет:

- HP-режим и необратимый бросок;
- выбор и замену заклинаний;
- подкласс;
- способ повышения характеристик;
- выбранные характеристики или черту.

При commit система:

1. валидирует базовую транзакцию;
2. валидирует все обязательные решения;
3. строит полное применение без изменения персонажа;
4. создаёт snapshot изменяемых полей;
5. применяет выборы;
6. выполняет базовый commit уровня;
7. откатывает snapshot, если базовый commit завершился ошибкой;
8. сохраняет единый итог.

## Миграция

Старые незавершённые транзакции сохраняют HP, бросок и заклинательные решения. В них добавляется пустой контейнер `level_choices`.

Для персонажей прежних версий:

- Воин уровня 3+ без подкласса получает документированный fallback `guardian_vanguard`;
- персонаж уровня 4+ без истории развития получает запись `legacy_preserved` без изменения характеристик;
- существующие происхождение, характеристики, XP, HP, ресурсы и заклинания не пересчитываются.

Миграция идемпотентна.

## Граница этапа

В текущий этап не входят:

- способности двух воинских подклассов;
- подклассы остальных классов;
- полный каталог черт;
- повторяемые черты;
- мультиклассирование;
- замена уже выбранного подкласса;
- ретроактивная выдача характеристик старому персонажу уровня 4+.

Новые типы выбора должны добавляться через `LevelChoiceSystem`, а не как отдельная логика внутри `LevelUpPanel`.
