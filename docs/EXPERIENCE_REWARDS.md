# Награды опыта

## Назначение

`ExperienceRewardSystem` является единственной точкой выдачи опыта за игровые события. Система отделяет источник награды от `ProgressionSystem`: источник сообщает стабильный `reward_id`, каталог определяет количество XP, а прогрессия только изменяет накопленный опыт.

```text
игровое событие
→ reward_id
→ ExperienceRewardSystem
→ проверка реестра полученных наград
→ ProgressionSystem.grant_experience
→ сохранение
→ мобильное уведомление
→ доступное повышение уровня
```

## Каталог

Определения находятся в `data/rewards/experience_rewards.json`.

```json
{
  "quest_first_steps_complete": {
    "experience": 300,
    "label": "Задание «Первые шаги»",
    "source_type": "quest",
    "source_id": "first_steps"
  }
}
```

`reward_id` является стабильным идентификатором сохранения. Его нельзя переименовывать после публикации без отдельной миграции.

## Одноразовость

Полученные ID хранятся в `GameState.story_flags` под ключом `_claimed_experience_rewards_v1`. Повторный вызов того же ID возвращает `duplicate: true` и не изменяет опыт.

Это защищает от повторной награды после:

- загрузки сохранения;
- повторного разговора;
- восстановления тренировочной цели;
- повторного вызова квестового события;
- повторного входа в область.

Повторяемое столкновение не должно использовать один постоянный ID. Для него требуется уникальный идентификатор экземпляра или отдельное утверждённое правило повторяемой награды.

## Источники текущего вертикального среза

- `quest_first_steps_complete` — 300 XP за завершение задания;
- `encounter_training_dummy_break` — 25 XP за первое разрушение тренировочной цели;
- `dialogue_caretaker_revelation` — 25 XP за первое успешное открытие тайны Смотрителя.

Три успешных проверочных варианта диалога используют один общий ID, поэтому нельзя получить награду три раза, перебирая реплики.

## Интеграция

Квест добавляет запись с `reward_id` в массив `rewards`:

```json
{
  "reward_id": "quest_first_steps_complete"
}
```

Диалоговая ветка использует поле:

```json
{
  "response": "...",
  "reward_id": "dialogue_caretaker_revelation"
}
```

Боевая или исследовательская система вызывает:

```gdscript
GameState.grant_experience_reward(
    "encounter_training_dummy_break",
    {"source_type": "encounter", "encounter_id": "training_dummy"}
)
```

## Сигналы

Расширенный autoload `game_state_rewards.gd` публикует:

```gdscript
experience_gained(reward_id, amount, total_experience, label)
level_up_available(current_level, target_level, pending_level_count)
experience_rewards_migrated(reward_count, experience_gained)
```

`ExperienceRewardToast` показывает мобильные уведомления. Открытый Character Hub обновляется по сигналу, но не хранит состояние награды.

## Миграция

При загрузке старого сохранения система проверяет завершённые квесты. Если квест уже завершён, но связанный `reward_id` отсутствует, опыт начисляется один раз без всплывающего уведомления и записывается в сохранение.

Боевая и диалоговая награды не восстанавливаются ретроактивно, потому что старое сохранение не содержит достаточных данных, подтверждающих конкретный результат.

## Проверки

Профильный CI проверяет:

- единичную выдачу;
- сохранение и загрузку реестра;
- идемпотентную миграцию завершённого квеста;
- совместимость предметной награды;
- диалоговую выдачу;
- мобильное уведомление;
- живое обновление Character Hub;
- появление кнопки повышения уровня после достижения порога.
