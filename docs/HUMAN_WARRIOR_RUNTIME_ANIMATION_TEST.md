# Проверка runtime-анимаций human_warrior_m01

## Назначение

Этап подключает художественно утверждённые кадры `human_warrior_m01` к Godot 4.7.1 для проверки в реальной игровой сцене. Он не добавляет атаку и не меняет боевые правила.

## Подключённые наборы

- `idle` — четыре направления, по одному кадру;
- `walk` — четыре направления, по шесть кадров, 8 FPS;
- `combat_idle_onehand` — четыре направления, по четыре кадра, 4 FPS;
- `combat_idle_twohand` — четыре направления, по четыре кадра, 4 FPS;
- `walk_onehand` — четыре направления, по шесть кадров, 8 FPS;
- `walk_twohand` — четыре направления, по шесть кадров, 8 FPS.

Источник вооружённой ходьбы: Blender workflow run `30704702485`, artifact `8820190573`, SHA-256 `b2c30af6199ca66449987f5737764649066cabc66589c9c4983107bcc3a09000`.

## Архитектура

Анимации описаны в `data/visuals/human_warrior_m01_runtime_v01.json`. Игровой код не содержит списков PNG-кадров. `HumanWarriorAnimationLibrary` собирает `SpriteFrames` из шести атласов с ячейкой `96×96`.

`AnimatedSprite2D` является дочерним узлом прежнего `Body`. Полигон становится прозрачным, но остаётся единым transform-root для существующих выпадов, прыжков и будущих анимационных переходов. Для других рас и классов сохраняется прежний процедурный fallback.

## Debug-панель

В debug-сборке для комбинации `human + fighter` сверху появляется панель:

- `АВТО` — выбор набора по реальному состоянию боя и экипированному оружию;
- `БЕЗ` — принудительно обычные idle/walk;
- `1Р` — одноручные combat idle/walk;
- `2Р` — двуручные combat idle/walk;
- `БОЙ` — временная визуальная имитация боевого режима, не запускающая инициативу и не меняющая сохранение.

Панель не создаётся в release-сборке.

## Ручная проверка Windows и Android

1. Создать или загрузить Человека-Воина.
2. Проверить `БЕЗ`, `1Р` и `2Р` во всех четырёх направлениях.
3. Начинать и останавливать движение, проверяя отсутствие скачка базовой линии.
4. Проверить смену направления во время движения и в idle.
5. В `АВТО` войти в настоящий бой и убедиться, что выбран набор экипированного оружия.
6. Проверить, что большой серебряный наплечник остаётся на физической левой стороне, а ножны и подсумок не меняют стороны.
7. На Android проверить читаемость при реальном масштабе, отсутствие размытия, стабильные 8 FPS и отсутствие перекрытия debug-панели критическим HUD.
8. Создать персонажа другой расы или класса и подтвердить безопасный процедурный fallback.

Ресурс становится runtime-approved только после этой физической проверки.
