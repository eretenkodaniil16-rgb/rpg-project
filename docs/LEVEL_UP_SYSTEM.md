# Система опыта и повышения уровня

## Назначение

Система заменяет прежнее автоматическое повышение по условной формуле XP на
последовательный, сохраняемый процесс по правилам SRD 5.2.1.

Опыт и применение уровня разделены:

1. `ProgressionSystem.grant_experience()` только начисляет опыт.
2. При достижении порога появляется доступ к следующему уровню.
3. `LevelUpSystem` создаёт транзакцию ровно для `текущий уровень + 1`.
4. Игрок выбирает прирост здоровья и доступные изменения магии.
5. Только подтверждение атомарно меняет персонажа и очищает транзакцию.

Это исключает частично применённые уровни и позволяет безопасно закрыть игру
на экране повышения.

## Пороги XP

Используются накопительные пороги уровней 1–20:

`0, 300, 900, 2700, 6500, 14000, 23000, 34000, 48000, 64000,
85000, 100000, 120000, 140000, 165000, 195000, 225000,
265000, 305000, 355000`.

При наличии опыта сразу на несколько уровней они применяются по одному.
Следующая транзакция становится доступна после завершения предыдущей.

## Здоровье

Для каждого нового уровня игрок выбирает один вариант:

- фиксированное значение Кости Хитов, округлённое вверх;
- один бросок классовой Кости Хитов.

К результату добавляются модификатор Телосложения и расовый бонус здоровья за
уровень. Итоговый прирост не может быть меньше 1.

Результат броска немедленно записывается в транзакцию. Повторное нажатие,
закрытие интерфейса или перезапуск игры возвращают тот же результат.

## Особенности и ресурсы

Особенности берутся из `level_features` соответствующего класса в
`data/classes/classes.json`. Система не содержит параллельного каталога
классовых особенностей.

После применения уровня:

- обновляется бонус мастерства через уровень персонажа;
- выдаются особенности нового уровня;
- синхронизируются ограниченные ресурсы особенностей без восстановления уже
  потраченных применений;
- добавляется одна Кость Хитов;
- обновляются расовые ресурсы, зависящие от бонуса мастерства;
- `SpellcastingSystem` пересчитывает лимит подготовки, ячейки и уровень ячеек
  договора, сохраняя уже потраченные ячейки.

## Заклинания

Транзакция работает с существующими источниками `class` и
`magic_initiate`, а не записывает заклинания напрямую в UI.

В пределах текущего каталога можно:

- добавить новое классовое заклинание;
- заменить одно изученное классовое заклинание для классов, использующих
  замену при повышении;
- заменить один заговор **или** одно заклинание черты
  «Посвящённый в магию».

Полные каталоги заклинаний уровней 2–9 будут расширять те же источники без
изменения формата транзакции.

## Сохранение и миграция

Транзакция хранится в `GameState.story_flags` под стабильным системным ключом,
поэтому уже входит в существующий формат сохранения версии 5.

Семантическая миграция:

- не уменьшает уровень или опыт;
- если старый персонаж имеет опыт ниже официального минимума своего уровня,
  опыт поднимается до этого минимума;
- устаревшая или относящаяся к другому уровню транзакция удаляется;
- миграция идемпотентна.

## UI

Экран `LevelUpPanel` создаётся динамически внутри `Interface` и рассчитан на
мобильное разрешение. Character Hub показывает кнопку повышения только при
доступном или незавершённом уровне.

Кнопка «ОТЛОЖИТЬ» закрывает экран, но сохраняет транзакцию. Сброс выбора
здоровья после броска не создаёт нового результата.

## Тесты

`tests/test_level_up_system.gd` проверяет:

- официальные пороги XP;
- отсутствие автоматического повышения;
- последовательные транзакции;
- фиксированное здоровье;
- необратимый бросок;
- выдачу особенности уровня;
- классовые и Magic Initiate изменения заклинаний;
- миграцию старого синтетического XP.

`tests/test_mobile_combat_progression_hud.gd` проверяет реальную игровую сцену,
Character Hub, панель повышения и отсутствие регрессий мобильного HUD.
