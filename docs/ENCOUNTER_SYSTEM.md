# Единая система столкновений

## Назначение

`EncounterSystem` связывает бой, диалоги, последствия, квестовые события, предметы, опыт и сохранения единым стабильным `encounter_id`. Сцена или UI больше не должны самостоятельно выдавать награду и отдельно менять несколько несвязанных флагов.

## Состояния

- `available` — столкновение известно системе, но ещё не начато;
- `active` — текущая попытка началась;
- `resolved` — выбран и зафиксирован способ разрешения, последствия применяются;
- `rewarded` — последствия и награда завершены;
- `failed` — текущая попытка закончилась поражением, её можно начать снова;
- `abandoned` — игрок покинул текущую попытку, её можно начать снова.

Для нерепетируемого столкновения состояния `resolved` и `rewarded` терминальны. Другой способ разрешения после них не применяется.

## Данные

Каталог находится в `data/encounters/encounters.json`.

Определение содержит:

- `id`;
- `title`;
- `repeatable`;
- `reward_id`;
- необязательный `combat_resolution_id`;
- словарь `resolutions`.

Каждый результат может содержать:

- `type`;
- `label` и `message`;
- `set_flags`;
- `quest_events`;
- `items`.

## API GameState

- `begin_encounter(encounter_id, context)`;
- `resolve_encounter(encounter_id, resolution_id, context)`;
- `fail_encounter(encounter_id, reason_id, context)`;
- `abandon_encounter(encounter_id, reason_id, context)`;
- `get_encounter_state(encounter_id)`;
- `get_encounter_status(encounter_id)`;
- `is_encounter_resolved(encounter_id)`;
- `get_active_encounter_ids()`.

Сигналы:

- `encounter_started`;
- `encounter_resolved`;
- `encounter_failed`;
- `encounter_abandoned`;
- `encounter_state_changed`.

## Сохранения

Реестр хранится внутри `story_flags` под namespaced-ключом `encounter_registry_v1`. Это сохраняет совместимость с текущей версией файла сохранения и не создаёт параллельный файл.

Записываются:

- статус;
- число попыток;
- `resolution_id` и тип результата;
- контекст начала и разрешения;
- состояние награды;
- последовательная история переходов.

Миграция восстанавливает:

- разрушенную тренировочную цель по ранее полученному `encounter_training_dummy_break`;
- раскрытую тайну Смотрителя по старой награде и сюжетным флагам;
- конкретный способ разговора, когда старые флаги позволяют его доказать.

Миграция идемпотентна и не начисляет опыт второй раз.

## Текущий вертикальный срез

### `training_construct`

- начинается при атаке на тренировочное чучело;
- боевой результат: `destroyed`;
- альтернативный предусмотренный результат: `disabled`;
- одноразово выдаёт XP и `straw_scrap`;
- восстановление визуального объекта не сбрасывает результат столкновения.

### `caretaker_revelation`

Одно столкновение может быть разрешено тремя способами:

- `persuaded`;
- `insight`;
- `history`.

Первый успешный способ фиксируется навсегда. Остальные варианты больше не меняют последствия и не дают повторную награду.

## Интеграция боя

`game_encounters_runtime.gd` расширяет текущий runtime подклассов. Актёр может предоставить `get_encounter_id()`. При начале боя runtime открывает столкновение; при победном завершении использует `combat_resolution_id`; при поражении героя фиксирует `failed`.

Новая система не заменяет `TurnBasedCombatSystem` и не меняет экономику действий.

## Ограничения этапа

Пока не входят:

- UI-журнал всех столкновений;
- бегство через границу зоны и автоматический `abandoned`;
- сложные условия победы из нескольких целей;
- сохранение точных позиций всех участников активного боя;
- генерация контрольной точки перед столкновением;
- массовая миграция будущих сцен.
