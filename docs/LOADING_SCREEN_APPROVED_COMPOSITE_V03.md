# Loading screen approved composite v03

## Назначение

Этот этап восстанавливает утверждённую композицию загрузочного экрана поверх runtime-переходов из PR №96. Механика асинхронной загрузки, сохранения и игровой runtime здесь не меняются.

## Художественный контракт

Источник композиции: утверждённый master `loading_screen_overlay_safe_v02.png`, реальный размер `1672×941`.

На master уже зафиксированы:

- цилиндрическая башня, уходящая вниз;
- лестницы и архитектурная перспектива;
- холодный голубой рунный свет и вертикальный луч;
- тёплые источники света;
- утверждённый синий заголовок `Хроники странника`;
- подзаголовок `Башня, уходящая вниз`;
- надпись `Загрузка...`;
- декоративная рамка полосы загрузки.

Композиция не регенерируется и не переинтерпретируется в этом PR.

## Игровой экспорт

Чтобы сохранить точные байты и не повторить повреждение крупных бинарников, master экспортирован как 26 вертикальных WebP-сегментов качества q82:

- `c00`–`c24`: `64×941`;
- `c25`: `72×941`;
- суммарная ширина: `1672`;
- максимальный размер одного файла: менее 15 КБ.

Manifest:

`res://assets/branding/loading_screen/approved/loading_screen_composite_v03/loading_screen_approved_composite_v03.json`

Для каждого сегмента фиксируются координата, размер, число байтов и SHA256.

## Renderer

`res://scripts/menus/loading_screen_approved_composite_v03.gd`

Renderer:

- использует cover-масштабирование с центрированием;
- сохраняет единый угол и композицию master;
- применяет nearest filtering;
- не включает texture repeat;
- добавляет overlap `0.75 px` между соседними полосами против субпиксельных швов;
- скрывается целиком, если отсутствует хотя бы один сегмент, оставляя безопасный fallback сцены.

26 draw calls допустимы: ресурс статичен и показывается только во время загрузочного перехода.

## Реальный прогресс

Система прогресса не дублируется. Используется существующий `loading_bar_v03` из PR №96.

Поскольку декоративная рамка уже находится внутри утверждённого master, для этой сцены выставляется:

`show_decorative_frame = false`

При этом остаются активны динамический fill/glint и живой процент загрузки. В остальных местах `loading_bar_v03` сохраняет прежнее поведение, так как значение параметра по умолчанию — `true`.

Чтобы не получить двойной текст поверх утверждённого master, `TitlePanel`, `SubtitlePanel` и `LoadingLabel` в runtime-сцене скрыты. Скрытые узлы оставлены для совместимости существующего API `set_status_text()` и fallback-контракта.

## Проверки

Автоматически проверяются:

- наличие всех 26 сегментов;
- размеры и SHA256 каждого сегмента;
- суммарный размер master `1672×941`;
- scene/script paths;
- отсутствие второго декоративного frame;
- Godot import и parser errors;
- runtime-инстанцирование сцены;
- `has_complete_tiles()`;
- фактическое обновление live percentage до `50%`.

## Android manual pass

До окончательного утверждения в игре необходимо проверить:

1. 16:9;
2. вытянутый Android-экран около 20:9;
3. отсутствие вертикальных швов;
4. читаемость встроенного логотипа и подзаголовка;
5. положение динамического fill относительно встроенной рамки;
6. 0%, 50% и 100%;
7. отсутствие нежелательного blur/anti-aliasing;
8. reduced motion;
9. реальный переход меню → создание персонажа и сохранение → игра после объединения зависимости PR №96.

Этот art-этап не считается финальным до визуальной проверки на устройстве.
