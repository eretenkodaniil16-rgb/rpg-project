# Loading screen approved composite v03

## Назначение

Этот art-only этап восстанавливает утверждённую композицию загрузочного экрана поверх runtime-переходов из PR №96. Механика асинхронной загрузки, сохранения и игровой runtime здесь не меняются.

## Художественный контракт

Исходный утверждённый reference master: `loading_screen_overlay_safe_v02.png`, `1672×941`.

На нём зафиксированы:

- цилиндрическая башня, уходящая вниз;
- лестницы и архитектурная перспектива;
- холодный голубой рунный свет и вертикальный луч;
- тёплые источники света;
- утверждённый синий заголовок `Хроники странника`;
- подзаголовок `Башня, уходящая вниз`;
- надпись `Загрузка...`;
- декоративная рамка полосы загрузки.

Композиция не регенерируется и не переинтерпретируется.

## Pixel master

По утверждённому направлению «сделать единственно более пиксельным» reference master уменьшен nearest-neighbor до `768×432` и экспортирован единым WebP q75:

`res://assets/branding/loading_screen/approved/loading_screen_composite_v03/loading_screen_approved_composite_v03.webp`

Контракт:

- размер: `768×432`;
- файл: `47 864` байта;
- SHA-256: `09484720511999dcff2b7be5311a74dad646d469af0c40b21856092770e38005`;
- фильтрация в Godot: nearest;
- texture repeat: disabled.

Единый master выбран вместо вертикальных полос: это полностью устраняет риск швов, сокращает число draw calls до одного и уменьшает объём ресурса для Android.

## Renderer

`res://scripts/menus/loading_screen_approved_composite_v03.gd`

Renderer использует cover-масштабирование с центрированием. При отсутствии master он скрывает себя целиком, поэтому базовый fallback загрузочной сцены остаётся рабочим.

Методы `has_complete_tiles()` и `expected_tile_count()` сохранены как compatibility API для существующего `LoadingScreenVisualV02`; `expected_tile_count()` теперь возвращает `1`.

## Реальный прогресс

Система прогресса не дублируется. Используется существующий `loading_bar_v03` из PR №96.

Поскольку декоративная рамка уже находится внутри утверждённого master, для этой сцены выставляется:

`show_decorative_frame = false`

Активными остаются динамический fill/glint и живой процент загрузки. В остальных местах параметр по умолчанию остаётся `true`.

Чтобы не получить двойной текст поверх master, `TitlePanel`, `SubtitlePanel` и `LoadingLabel` в runtime-сцене скрыты. Скрытые узлы сохранены для compatibility/fallback API.

## Безопасная материализация

GitHub-коннектор в текущей среде подтверждённо искажает бинарные WebP при прямой загрузке. Поэтому одноразовый transport хранит только текстовые base64-фрагменты. Materializer сначала собирает файл и проверяет его размер и SHA-256, и только затем коммитит настоящий WebP. При несовпадении контрольной суммы ветка не изменяется.

Transport и сам materializer должны быть удалены тем же materialization-коммитом и не входят в финальный PR diff.

## Автоматические проверки

Проверяются:

- точный размер и SHA-256 единого WebP;
- RIFF/WEBP signature;
- manifest `768×432`, q75 и nearest-neighbor contract;
- отсутствие полос и seam-overlap логики;
- scene/script paths;
- отсутствие второго декоративного frame;
- Godot import/parser errors;
- runtime-инстанцирование сцены;
- `has_complete_tiles()` и `expected_tile_count() == 1`;
- обновление live percentage до `50%`;
- отсутствие временного transport/materializer в финальном пакете.

## Android manual pass

До окончательного утверждения в игре необходимо проверить:

1. 16:9;
2. вытянутый Android-экран около 20:9;
3. пиксельную резкость без blur/anti-aliasing;
4. читаемость встроенного логотипа и подзаголовка;
5. положение динамического fill относительно встроенной рамки;
6. 0%, 50% и 100%;
7. reduced motion;
8. реальный переход меню → создание персонажа и сохранение → игра после объединения зависимости PR №96.

Этот art-этап не считается финальным до визуальной проверки на устройстве.
