# Асинхронные переходы сцен v01

## Назначение

`SceneTransitionManager` — единая точка для тяжёлых переходов между крупными сценами. Он показывает загрузочный overlay, запускает `ResourceLoader.load_threaded_request()`, читает фактический прогресс через `load_threaded_get_status()` и переключает сцену только после `THREAD_LOAD_LOADED`.

## Интегрированные маршруты

Первый проход намеренно ограничен переходами, где загрузочный экран даёт реальную пользу:

- главное меню → создание персонажа;
- выбранное сохранение → `game.tscn`;
- завершение создания персонажа → `game.tscn`.

Локальные окна, диалоги, инвентарь, лист персонажа, пауза и обычные взаимодействия не используют загрузочный экран.

## Контракт менеджера

- одновременно разрешён только один запрос;
- текущая сцена остаётся активной до успешной загрузки цели;
- целевая сцена загружается с `CACHE_MODE_REUSE`;
- `use_sub_threads=false`, чтобы не усиливать кратковременную нагрузку на главный кадр Android;
- прогресс полосы берётся из `ResourceLoader`, а не из таймера;
- минимальное время отображения — 0,35 секунды, чтобы избежать краткого мерцания overlay;
- при ошибке загрузки overlay снимается, текущая сцена остаётся доступной;
- после `THREAD_LOAD_LOADED` используется `change_scene_to_packed()`.

## Loading visual

Runtime-сцена:

`res://scenes/menus/loading_screen_visual_v02.tscn`

Она использует:

- восстановленный утверждённый пиксельный фон цилиндрической башни с синими гобеленами;
- точный живой заголовок `Хроники странника`;
- точный живой подзаголовок `Башня, уходящая вниз`;
- утверждённую модульную полосу `loading_bar_v03`;
- фактический процент загрузки;
- лёгкую пульсацию света, отключаемую через `accessibility/reduced_motion`.

## Важный статус графики

При проверке после слияния PR №95 обнаружено, что в `main` попали только незавершённые transport/materializer-файлы, а заявленные `loading_screen_visual_v02.tscn` и финальные бинарные слои башни отсутствовали. Integration-pass удалил временный транспорт и восстановил рабочую runtime-сцену.

Следующий art-only pass восстановил точный утверждённый пиксельный фон из сохранённого исходного PNG с проверяемой контрольной суммой. Фон загружается динамически и не содержит текста или UI; при его отсутствии остаётся тёмная заливка, поэтому асинхронный переход не зависит от графического ресурса. До физического теста фон сохраняет статус `runtime_candidate`, а не `final`.

## Fallback вызовов

Точки вызова получают `/root/SceneTransitionManager` динамически. Если autoload отсутствует из-за повреждённой конфигурации проекта, сохраняется прежний прямой `change_scene_to_file()` как аварийный fallback. Если менеджер существует, повторный запрос не обходит его busy guard.

## Следующее расширение

После проверки первого прохода тот же менеджер можно подключать к действительно крупным межлокационным переходам и перезагрузке сохранения после смерти. Обычные двери внутри уже загруженной игровой сцены не должны использовать этот overlay.
