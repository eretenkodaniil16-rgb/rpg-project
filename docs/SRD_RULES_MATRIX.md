# Реестр правил SRD 5.2.1

Этот файл — единый технический реестр правил проекта. Он фиксирует, на какой редакции основана игра, что уже реализовано, где используется временное упрощение и какие механики ещё нельзя считать соответствующими SRD.

Документ не воспроизводит полный текст SRD. Формулировки ниже являются краткими инженерными описаниями реализации.

## Канонический стандарт

- `ruleset_id`: `srd_5_2_1`
- основа: **System Reference Document 5.2.1**;
- лицензия открытого материала: **CC BY 4.0**;
- игровой мир, сюжет, персонажи, названия, визуальный стиль и авторские особенности проекта остаются оригинальными;
- правила 2014 года и правила SRD 5.2.1 нельзя смешивать без явной записи в этом файле;
- любое намеренное отступление помечается `game_adaptation`;
- внутренние стабильные идентификаторы не переименовываются без миграции сохранений.

Официальные источники:

- https://www.dndbeyond.com/srd
- https://www.dndbeyond.com/sources/dnd/br-2024
- https://creativecommons.org/licenses/by/4.0/

## Статусы

| Статус | Значение |
|---|---|
| `implemented` | Реализовано в коде и имеет автоматическую проверку. |
| `partial` | Работает только часть правила или отсутствует важный выбор/ограничение. |
| `planned` | Зафиксировано в архитектуре, но ещё не реализовано. |
| `must_fix` | Текущая механика противоречит SRD и должна быть исправлена до содержательного релиза. |
| `game_adaptation` | Намеренное правило проекта, не выдаваемое за буквальное SRD. |

## Обязательное правило совместимости

Старые сохранения не получают происхождение и увеличение характеристик автоматически. Игрок сохраняет прежние итоговые значения. Служебный `legacy_origin` отмечает, что персонаж создан до перехода на SRD 5.2.1.

# 21. Definition of Done для механики SRD

Механика считается соответствующей реестру только когда:

- правило связано с `ruleset_id`;
- данные отделены от UI;
- есть стабильные идентификаторы;
- старые сохранения загружаются без изменения уже полученных значений;
- игрок и NPC используют одно общее ядро там, где правило одинаково;
- преимущества, помехи, владение и состояния не рассчитываются параллельными системами;
- есть автоматический тест нормального случая и хотя бы одного запрещённого случая;
- мобильный UI позволяет выполнить действие без скрытых обязательных жестов;
- любое отступление от SRD помечено `game_adaptation` в этом файле;
- PR проверен и не объединён без прямого подтверждения пользователя.
