# Реестр правил SRD 5.2.1

Этот файл — единый технический реестр правил проекта. Он фиксирует каноническую редакцию, фактическое состояние реализации, временные упрощения и намеренные игровые адаптации.

Документ не воспроизводит полный текст SRD. Формулировки являются краткими инженерными описаниями реализации.

## Канонический стандарт

- `ruleset_id`: `srd_5_2_1`;
- основа: **System Reference Document 5.2.1**;
- лицензия открытого материала: **CC BY 4.0**;
- правила 2014 года и SRD 5.2.1 нельзя смешивать без явной записи здесь;
- намеренное отступление всегда помечается `game_adaptation`;
- стабильные идентификаторы не переименовываются без миграции сохранений;
- игровой мир, сюжет, персонажи, названия и визуальный стиль остаются оригинальными.

Официальные источники:

- https://www.dndbeyond.com/srd
- https://www.dndbeyond.com/sources/dnd/br-2024
- https://creativecommons.org/licenses/by/4.0/

## Статусы

| Статус | Значение |
|---|---|
| `implemented` | Реализовано и покрыто автоматической проверкой. |
| `partial` | Работает часть правила либо отсутствует важный выбор или ограничение. |
| `planned` | Зафиксировано, но ещё не реализовано. |
| `must_fix` | Текущая механика противоречит стандарту и блокирует содержательный релиз. |
| `game_adaptation` | Намеренное правило проекта, не выдаваемое за буквальное SRD. |

# 1. Создание персонажа

| Система | Статус | Реализация и ограничения |

| Классовые спасброски | `implemented` | Загружаются из данных класса. |
| Классовые навыки | `planned` | Нужен выбор с защитой от дублирования происхождения. |
| Владение оружием и обучение броне | `planned` | Поля модели готовы, игровые последствия не подключены. |
| Миграция старого персонажа | `implemented` | Старые характеристики не пересчитываются; используется `legacy_origin`. |

Старые сохранения не получают новое происхождение, бонусы и комплект автоматически.

# 20. Приоритет следующих этапов

1. Завершить классовые навыки, владения оружием и обучение броне.
2. Добавить полный выбор заклинаний Magic Initiate и классовых заклинаний.
3. Реализовать прогрессию слотов и каталог заклинаний уровней 2–9.
4. Добавить материальные компоненты, фокусы и занятые руки.
5. Создать универсальные области заклинаний и выбор клеток.
6. Добавить UI выбора комплекта происхождения или 50 зм.
7. Довести короткий и долгий отдых до точных ограничений.
8. Завершить Воина первого уровня и мастерства оружия.
9. Унифицировать скрытность, свет, линию обзора и укрытие.
10. Добавить таблицы классов 1–20, подклассы и общие черты.
11. Создать полные stat block монстров и тактический ИИ.
12. После этого рассматривать мультиклассирование и высокие уровни.

# 21. Definition of Done для механики SRD

Механика считается соответствующей реестру, когда:

- связана с `ruleset_id`;
- данные отделены от UI;
- используются стабильные идентификаторы;
- старые сохранения загружаются без изменения ранее полученных значений;
- игрок и NPC используют общее ядро там, где правило одинаково;
- нет параллельных расчётов преимущества, владения, состояний или ресурсов;
- есть автоматический тест разрешённого и запрещённого случая;
- мобильный UI позволяет выполнить действие без скрытых обязательных жестов;
- отступления явно помечены `game_adaptation`;
- PR проверен и не объединён без прямого подтверждения пользователя.
