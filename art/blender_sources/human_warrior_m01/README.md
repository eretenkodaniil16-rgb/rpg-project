# Blender source — human_warrior_m01

Этот каталог хранит производственный 3D-источник персонажа, но не игровые
ресурсы. Godot не импортирует его благодаря `.gdignore`.

Структура:

```text
human_warrior_m01/
├── textures/
│   ├── pilot_v01/    # заменяемые texture slots пилотной модели
│   └── approved/     # только утверждённые текстуры
├── source/           # утверждённые .blend и внешние mesh-исходники
├── work/             # ручная доработка и промежуточные версии
├── exports/          # временные 3D-экспорты
├── frames/           # отрендеренные одиночные кадры до утверждения
└── atlases/          # собранные атласы до переноса в assets/
```

Автоматический пилот пишет каждый запуск в игнорируемый каталог
`art/blender_pipeline_runs/`, поэтому он не может перезаписать утверждённый
`.blend` или игровой PNG.

`textures/pilot_v01` — технические низкоразрешённые текстуры, полученные из
палитры утверждённого master-reference. Они нужны для проверки UV/material
контракта, но пока не являются финальной художественной палитрой. Замена PNG с
тем же именем меняет материал без изменения рига и анимаций.

После ручной проверки в Blender и Godot:

1. утверждённый `.blend` копируется в `source/`;
2. утверждённые текстуры — в `textures/approved/`;
3. только проверенные PNG-кадры переносятся в
   `assets/characters/human/warrior_m01/gameplay/frames/`;
4. атлас собирается отдельно и не заменяет source-файлы.
