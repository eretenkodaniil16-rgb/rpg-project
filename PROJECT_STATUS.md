## Интеграционный контракт v0.18

Автоматическая проверка `tests/test_v018_integration_stack.gd` подтверждает:

- autoload `GameState` указывает на `game_state_stealth_alerts.gd`;
- итоговый `GameState` содержит API наград, encounter и stealth-alert;
- XP-награда, `abandoned` encounter, тревога NPC и состояние двери записываются в один save-файл;
- реестры `_claimed_experience_rewards_v1`, `encounter_registry_v1` и `stealth_alert_registry_v1` переживают загрузку;
- игровая сцена использует `game_pursuit_escape_runtime.gd`;
- окно повышения уровня использует допустимый `z_index`;
- в HUD остаётся одна нижняя кнопка `ДЕЙСТВИЯ` и отдельная кнопка `ЦЕЛЬ`.

Профильный workflow: `.github/workflows/validate-v018-integration.yml`.

## Проверка после каждого будущего merge

1. Убедиться, что следующий PR основан на фактическом новом head.
2. Проверить `project.godot` и autoload `GameState`.
3. Проверить script root у `scenes/game/game.tscn`.
4. Запустить профильный workflow PR.
5. Запустить `Validate Godot project`.
6. Собрать обычную Android APK и Mobile Test APK.
7. Загрузить сохранение версии 5, созданное предыдущим этапом.
8. Проверить отсутствие повторной XP-награды и повторного разрешения encounter.
9. Не объединять следующий PR при красном обязательном workflow.

## Ручная проверка на Android

До объявления v0.18 проверенной пользователь должен подтвердить на физическом устройстве:

- кнопка `ЦЕЛЬ` остаётся в исследовании и бою;
- нижняя кнопка `ДЕЙСТВИЯ` открывает меню одним нажатием;
- кнопки не перекрывают маршрут, `АТАКУ` и `КОНЕЦ ХОДА`;
- дозорный проходит только через открытую дверь;
- подкрепление один раз присоединяется к инициативе;
- скрытность, поиск и сложное бегство читаются без точных процентов;
- сохранение и загрузка сохраняют XP, encounter, тревогу и дверь.
