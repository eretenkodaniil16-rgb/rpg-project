# Обновляемые Android test APK

Этот каталог содержит только постоянную подпись для внутренних тестовых сборок Android.

## Назначение

Workflow `.github/workflows/mobile-test-apk.yml` собирает отдельное тестовое приложение:

- package ID: `com.eretenkodaniil.rpgproject.test`;
- отображаемое имя: `Хроники странника — тест`;
- версия: `0.17.0-test.<github_run_number>`;
- versionCode: `100000 + github_run_number`;
- alias тестового ключа: `rpgtest`;
- SHA-256 файла PKCS#12: `9c79ad7e6e452257ec46c47ace4ab8a67c10d95ca6453d73e45d9efa39e3b643`;
- SHA-256 сертификата: `9D:63:FF:8D:41:3F:1B:FE:D5:78:A7:48:1F:32:6A:BD:9F:F5:3B:A6:24:E0:A7:E9:26:DF:43:93:C2:7B:8A:48`.

После первой установки этой test-сборки следующие APK из того же workflow устанавливаются поверх неё через системное действие Android `Обновить`. Данные приложения сохраняются, поскольку package ID и сертификат остаются неизменными, а versionCode увеличивается.

## Первое переключение

Старые CI APK использовали новый временный debug-ключ при каждом запуске. Они не могут быть обновлены новой схемой подписи.

Тестовое приложение использует отдельный package ID, поэтому первая обновляемая сборка устанавливается рядом со старой и не требует немедленного удаления старого приложения. Сохранения двух приложений изолированы Android и автоматически между ними не переносятся.

## Хранение тестового ключа

Публичный тестовый PKCS#12 хранится в четырёх небольших base64-частях:

- `rpg-project-test.keystore.b64.part01`;
- `rpg-project-test.keystore.b64.part02`;
- `rpg-project-test.keystore.b64.part03`;
- `rpg-project-test.keystore.b64.part04`.

Workflow соединяет части в фиксированном порядке, декодирует их и до обращения к `keytool` проверяет SHA-256 восстановленного файла. Это предотвращает выпуск APK с повреждённой или случайно заменённой подписью.

## Ограничение безопасности

Эти base64-части являются публичным тестовым ключом и не являются секретом. Их запрещено использовать для:

- релизного APK или AAB;
- Google Play;
- package ID `com.eretenkodaniil.rpgproject`;
- распространения пользовательской production-сборки.

Будущий релиз обязан использовать отдельный закрытый ключ, хранящийся вне репозитория или в GitHub Secrets.

## Проверки CI

Перед публикацией workflow проверяет:

1. SHA-256 восстановленного файла PKCS#12;
2. SHA-256 сертификата ключа и готового APK;
3. package ID внутри APK;
4. совпадение versionCode с вычисленным номером сборки;
5. успешный импорт Godot и мобильный regression-тест.

Артефакт содержит APK и `build-info.txt` с идентичностью конкретной сборки.
